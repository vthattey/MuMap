(d) Selection & hover affordances

These behave like every other tile, not a special case

Same resize handle, connector dots, and outline treatment regular sticky tiles already have. Rectangle-ish shapes (Terminator, Process) use the native outline property, same as today. Decision and Input/Output use CSS clip-path for their fill, and a native outline would just draw a rectangle around the bounding box — so their selection ring is a second clipped layer sized a few px larger behind the fill, giving a diamond/parallelogram-shaped ring instead. Hover this row for real; the "Selected" and "Connecting" columns are pinned open so you can see them without needing a live drag.

Decisions baked into this mock — please confirm or redirect

None of these are in the plan verbatim; they're the calls made to turn "4 shapes + lean chrome" into actual pixels.

  1. 1
    Exact dimensions: Terminator 170×56, Process 200×72, Decision 190×130, Input/Output 200×76. Decision is deliberately wider than tall (standard flowchart proportion) rather than square.
  2. 2
    Default fill colors reuse 4 existing swatches already in SWATCHES (green/blue/amber/purple) rather than introducing new brand colors or defaulting all 4 to white/neutral like draw.io. Still recolorable via the existing color picker.
  3. 3
    Process keeps the app's 14px corner rounding (same as every sticky tile) instead of switching to sharp draw.io-style rectangle corners — prioritizing visual continuity with the rest of the board over flowchart-notation purism.
  4. 4
    Long-label handling: Decision truncates at 2 lines + ellipsis inside a centered ~62%-width safe zone (clear of the sloped edges); Process/Input-Output clamp at 3/2 lines + ellipsis. Text never auto-shrinks font size and never overflows outside the shape's silhouette the way draw.io lets it.
  5. 5
    Decision/Input-Output selection ring is implemented as a second clip-path layer behind the fill (since native outline can't follow a clip-path silhouette), rather than switching those two shapes to a different selection indicator (e.g. a glow, a corner-only marker) than the rest of the board uses.
  6. 6
    Connector dots/resize handle reuse the existing 4-bounding-box-side positions unchanged for all 4 shapes — for Decision this happens to land exactly on its 4 vertices; for Input/Output the left/right dots sit near, not exactly on, the slanted edge (same approximation the app already accepts for circular tiles).
  7. 7
    Template example uses two separate "End" terminators (one per Yes/No branch) rather than merging both branches back into a single End node, to keep the connector routing simple and avoid a backward-pointing arrow. Input/Output isn't used in the template itself, only in the standalone shape gallery, since the plan's template description doesn't call for it.
